# Results

Measured outputs of the reported experiment: 5 PolyBench/C programs x 5 methods x 5 seeds (0-4) x 20 evaluations = 125 searches (2,500 evaluations).

| File | Content | Paper |
|---|---|---|
| `results.csv` | every single evaluation (method, seed, eval_idx, runtime, size, compile_time, elapsed, failed, seq) | Tables 6, 8 |
| `final.csv` | verified, re-timed best sequence per search (10 timings, correctness-checked) | Table 5 |
| `baseline.csv` | `-O3` and unoptimized (`-O0`) runtimes, output hash per program | all speedups |
| `per_run.csv`, `per_program.csv`, `summary.csv` | metrics per run / program / method (`run_all.py analyze`) | Tables 5-6 |
| `verified_vs_search.csv` | verified vs search-time speedup, bootstrap CI, beat rates | Tables 5, 6 |
| `per_benchmark_verified.csv` | mean +- std over seeds per benchmark | Table 7 |
| `failure_rate.csv`, `tuning_time_breakdown.csv` | failed builds, compile/execute/other seconds | Table 8 |
| `paired_tests.csv` | Wilcoxon, proposed vs each other method | Table 9 |
| `paired_cost_tests.csv` | exploratory search-cost comparisons (regenerated by `analysis/extra_stats.py`) | Table 10 |
| `passes_ok.json`, `warm.json` | pass list used (26 incl. `none`); warm-start sequences | - |
| `convergence.png`, `per_program_speedup.png`, `speedup_boxplot.png`, `summary_six_params.png` | graphs from `run_all.py analyze` | - |

## Headline numbers (verified speedup vs `-O3`, geometric mean of 25 runs)

| Method | Speedup [95% CI] | Failed builds/search | Tuning time (s) |
|---|---|---|---|
| Random Search | 0.947 [0.906, 0.982] | 1.12 | 65.1 |
| Genetic Algorithm | 0.917 [0.860, 0.966] | 0.64 | 64.7 |
| TPE | 0.952 [0.923, 0.977] | 1.32 | 68.1 |
| Proposed (GP-BO, sequence kernel, warm start) | 0.942 [0.885, 0.981] | 0.40 | 51.6 |
| Proposed, no warm start | 0.933 [0.876, 0.981] | 0.56 | 54.4 |

No method beats `-O3` on average, and no paired Wilcoxon test of the proposed method against another method is significant (all p > 0.3).

## Reproducing the derived tables

`bash scripts/analyze.sh` regenerates `summary.csv`, `per_program.csv`, `per_run.csv`, the PNGs and the statistics files from
`results.csv` / `final.csv` / `baseline.csv`. Verified on the shipped data:
`summary.csv`, `per_program.csv`, `per_run.csv`, `failure_rate.csv`, `tuning_time_breakdown.csv`, `per_benchmark_verified.csv` and the Table 9 p-values
reproduce exactly. Two things differ slightly because they depend on RNG / tie handling: the bootstrap CI bounds (about 0.002-0.003 from the shipped
values) and the Table 10 p-values (SciPy tie handling; e.g. evals-to-beat vs TPE comes out at p ~ 0.005 instead of 0.003). The conclusions do not change.
